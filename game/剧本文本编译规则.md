## 2. 手改统一使用这些符号

每个物理行表示一条内容；**推荐使用键盘直接输入的半角中括号 `[]`**，例如 `[旁白]`、`[台词]`。原来的 `〔旁白〕`、`〔台词〕` 等内容标签继续兼容，无需重改旧文本。角色与台词之间可以用中文冒号 `：`，也可以用英文冒号 `:`。不支持跨行标签或把一条台词拆成多行续写。

| 内容 | 推荐写法 | 编译与显示结果 |
| --- | --- | --- |
| 人物语言 | `[台词]基生：你还好吗？` | 对话框显示角色名和台词；一行一个人 |
| 保留的旁白 | `[旁白]夜色渐深，海面泛起蓝光。` | 显示在画面中央文字层，无角色名、无底部对话框 |
| 画面文字／字幕 | `[画面]十年之后` | 与旁白相同，显示在画面中；`[字幕]` 是同义标签 |
| 不保留的旁白／整行内容 | `[删除]原来的文字` | 不显示，不要求额外点击；可保留原文供编辑参考 |
| 人物内心活动 | `[内心]基生：她真的回来了吗？` | 整行不显示；`[心声]` 同样不显示 |
| 表情、语气、动作说明 | `[演出]基生惊恐地后退一步。` | 不显示；新标签本身不会自动驱动立绘、动画或音效 |
| 编辑备注 | `[备注]这里稍后核对台词归属。` | 不显示 |
| 空行 | 空行 | 忽略 |

`[删除]`、`[内心]`、`[心声]`、`[备注]`、`[演出]` 只控制本行，不延伸到下一行。未知 `[标签]` 会让编译报错，以免拼错标签后直接混入游戏。

**旁白的两种处理方式需要编辑者明确选择：保留就用 `[旁白]`，不要就用 `[删除]` 或删去整行。不要把内心独白改成 `[画面]` 来保留显示。** 无标签的旧叙述暂时按画面旁白处理；其中混有心理描写时，需要手动拆分或标成 `[内心]`，编译器不会凭语义猜测。

## 3. 括号、表情和真正的心声

人物名或台词中的全角圆括号 `（…）`、半角圆括号 `(...)` 均保留给非台词说明，编译时去掉括号及内部文字，支持嵌套。台词正文确实要说出口的词不能放在圆括号里。旁白／画面文字中的圆括号是正文，不会自动删除。

```text
[台词]基生（惊恐地）：（后退一步）你是谁？！
```

实际对话框：角色名 `基生`，台词 `你是谁？！`。

```text
基生（惊恐地）
[台词]基生：你是谁？！
```

第一行只是说明，直接跳过；第二行仍正常显示。不会因为去掉说明而连带删除接下来的台词。推荐把第一行整理成 `[演出]基生惊恐地后退一步。`。

```text
[内心]基生：这怎么可能……
[台词]基生：你是谁？！
```

这里第一行是人物真正的内心思考，整句不显示；第二行照常显示。名字中标有「内心／心声／心理活动／内心独白」的旧台词也会整句跳过。

## 4. 旧文本兼容规则

| 现有写法 | 处理方式 |
| --- | --- |
| `基生：台词` 或 `基生:台词` | 人物语言；建议统一成 `[台词]基生：台词` |
| `基生　「台词」` | 人物语言；外层 `「」` 不显示 |
| `旁白：叙述` | 画面文字，不进对话框 |
| `［ 画面文字 ］` | 保持画面文字；注意这是全角方括号 `［］` |
| `〔内心〕…`、`〔心声〕…` | 整行跳过；与 `[内心]`、`[心声]` 相同 |
| `基生（内心）：…`、`基生（心声）：…` | 整行跳过 |
| `（ILY·心声）「…」` | 整行跳过 |
| 无标签的普通叙述 | 暂按画面旁白显示；手改时明确补 `[旁白]`／`[删除]`／`[内心]` |
| 第一章旧的 `“一句”｜“另一句”` | 保留原有交替分配规则；本轮不纠正已有错位。新写台词请逐行明确角色，不再用这种压缩写法 |

`[台词]` 后面不要再包一层 `「」` 或 `“”`，否则这些引号属于正文，会原样显示。普通台词不要写成 `【台词】` 或 `(台词)`；这些不是本规则的内容标签。圆括号仍用于表情、动作等说明。

## 5. 场景、分支、玩法和制作标记

这一轮统一的是**文本内容分类**。已有剧情结构继续由各章编译器处理，不能把控制标记当成旁白删掉，也不能仅靠新增同名标记创建新玩法。

| 原有结构 | 手改要求 |
| --- | --- |
| 男主篇 `S01 ｜ 场景标题`、`S07-E`、`S07A` 等 | 保留编号、分隔符和顺序；场景标题作为画面文字 |
| 女主篇 `序章｜青`、`第一章｜看不见的她` 等 | 保留原结构；显示章节标题卡 |
| 女主篇 `01－01　便利店…` | 保留编号、全角连字符 `－` 和全角空格；显示场景标题卡 |
| `◆ 分歧节点…`、`【A 线】`、`【B 线】`、`◆ 合流…` | 保留原样。第一章行内分支标记放在内容标签之前，如 `【B 线】[台词]基生：……` |
| `〔疑点 P# 记录〕`、原有独立疑点标记 | 保留原样；控制线索收集，不是普通台词 |
| `【Gameplay G#…】`、`◆ Gameplay…` | 保留原样；控制已有 RPG／小游戏入口 |
| `选项 A：…` 等旧设计稿说明 | 不是可自由编译的新选项语法；实际选项和目标目前定义在编译器里 |
| `◆ 演出…`、`【背景】`、`【立绘】`、`【BGM】`、`【SE】`、`【特效】`、`【演出】` | 保留原有格式；已有生成器按各章规则处理，说明不进入对话框。女主篇部分信息仅保留为制作元数据，不代表已接入声音或动画 |
| `时间：…`／`地点：…` | 保留原结构；第一章时间地点显示为画面文字，其余章节按原流程处理 |
| `附录 A…`、`终章字幕…`、`——此处接回最终章——` 等 | 保留原位置，它们可能是正文编译的结束标记 |
| 最终章 `收信` 及其日期、发件人、正文 | 保留原结构，使用专用信件界面 |

部分 CG、背景切换和剧情锚点目前仍通过原文关键词触发。**修改场景标题以外的关键叙述、给触发行补标签、改变分支或插入新场景后，需要检查相应画面和流程；标签不会自动重写这些演出触发规则。** 需要新增分支、改选项或新增素材映射时，应同步修改编译器，不能只改 TXT。

## 6. 可直接照着改的例子

原文：

```text
基生（惊恐地）：（退后一步）爱理……你是谁？
[内心]她不可能是我认识的那个人。
海风穿过两人之间。
这一段只是整理时的备注。
```

整理后：

```text
[演出]基生惊恐地退后一步。
[台词]基生：爱理……你是谁？
[内心]她不可能是我认识的那个人。
[旁白]海风穿过两人之间。
[备注]这一段只是整理时的备注。
```

游戏依次显示：基生的对话框 → 海风旁白的画面文字。其余三行没有文字显示，也没有空白等待。

## 7. 修改与重新生成

1. 在第 1 节所列原位置 TXT 中修改，保存为 UTF-8。
2. 在仓库根目录运行 `npm run build:story`，一次生成全部五份章节 JS（需要 Python 和 Node.js）。只改女主篇也可以运行 `npm run build:heroine`。
3. 运行 `npm test` 检查章节连接、分支、线索与显示规则；修改编译器时另运行 `npm run test:script-rules` 检查 Python／JavaScript 对同一组符号例子的解析一致性。
4. 从游戏入口预览修改所在段落：台词只含说话内容、旁白在画面中、没有心声和空对话框。改动较大时使用新流程试玩，自动编号在增删文本后可能变化。

不要直接修改生成的章节 JS，否则下次生成会覆盖。共享符号定义为 `tools/script-rules.json`，Python 与 JavaScript 编译器共用它。

实现上，跳过的原句会保留一个空的 `cue` 节点，保证本次更新尽量保留旧节点编号、分支锚点与线索触发；运行时直接越过，原来的内心文字不写入生成文件。画面文字使用 `monologue` 节点（这里只是已有显示模式名称，不代表允许保留人物内心活动）。选择题显示为「选择」，属于交互界面，不冒充人物心声。

## 8. 当前文本状态

本轮已将实际编译文本和参考稿中原本可识别的内容逐行标出 [旁白]、[台词]、[内心]、[画面]。人物台词中的括号说明已删除；修改前快照保存在 game/script-backups/before-labeling-20260915-222331/，其中 labeling-report.json 记录各文件的标注数量。以后新增内容直接沿用这些标签。

游戏运行时右上角的「剧本编辑」按钮会显示当前节点并高亮当前文本。修改后点击「保存本句」会保存到本机浏览器并立即用于当前游玩；「导出修改稿」会下载 JSON 修改记录。浏览器无法直接写回工作区 TXT，正式合并到剧本时请把导出的内容对应改回原 TXT，再运行 npm run build:story。`r`npm run build:story。


游戏内的「剧本校对」面板同时支持文本修改和类型归类：当前执行句会高亮，场景内其他句子会一起列出；每句都有文本框和类型下拉框。保存内容只写入浏览器本地，导出 JSON 后再回填原 TXT。

校对器现在是独立窗口：游戏点击推进不会被面板阻塞，校对窗口会通过消息实时跟随当前节点和场景。关闭或删除 script-editor 入口、页面和脚本即可移除，不影响正文播放。

校对窗口点击「保存修改」后，已有文本段和新增段的分类都会参与播放：台词使用对话框，旁白沿用女主线的居中文字与逐字显示，内心／演出直接跳过。序章原有说话人为「旁白」的段落默认使用画面文字，已保存的明确分类优先；女主线标题卡保留标题样式。当前正在显示的文本会立即刷新，选项、手机与玩法节点保留交互类型。修改仍只保存到当前浏览器的本地存储，不会自动写回源文件。
