## P1 — Sol：最小可用闭环

按技术提案建立独立配音编辑器，优先复用项目现有Node/浏览器环境。先给出简短实施思路，随后完成实现。

仅实现：本机引擎连接及错误提示、动态声音/风格列表、多选TXT导入及分句预览、可编辑speechText、独立displayText、单句基本参数（语速/音高/抑扬/音量/前后留白）、生成试听、独立工程保存/打开、单句WAV导出。导入记录须从第一版就有稳定ID和版本字段。文本改变应使旧查询和试听失效；晚返回的请求不得覆盖新文本。已选风格缺失时显示待重新映射，不静默替换。

请实现可恢复且校验过的工程保存路径，保留人工参数，错误不能报告为成功；保存模型为后续逐mora编辑预留完整AudioQuery。给出明确中文启动说明。在样例中使用少量日语，不默认翻译实际剧情。至少验证：引擎不可达、TXT导入及重复行、参数保存重开、过期试听竞态、无效工程文件、真实引擎一小段生成有效WAV。UI检查导入→选择→调节→试听→保存→重开→导出。真实声音审美标记待人工听审。

不要做全量批生成、morphing、原版vvproj互通或游戏运行时改造。只有通过上述闭环后才报告P1完成。

## T1 — Sol：先准备角色日语台词稿的上游工具

本任务优先于正式游戏配音，可在P1之前完成。用户明确要求先生成各角色日语文本文件，再交VOICEVOX。请实现有效中文剧本提取与按角色导出中日对照待译稿的工具：复用六篇剧情及已发布script-edits的覆盖、插入、删除、分类语义，输出稳定ID、章节/场景、原顺序、角色、中文原文、待填日文、校对状态与必要的上下文引用。翻译工作要能恢复场景顺序，不能只有脱离上下文的角色孤立句子。

支持按稳定ID回导翻译后的角色CSV/TSV，保留原文，检查丢失/重复/未知ID、空日文和源文变化。可提供日语TXT及配套ID清单的导出，但不要仅靠行号或日文内容重配游戏ID。VOICEVOX不负责翻译，不将中文自动塞进speechText，也不在此阶段擅自翻译全篇。输出少量显式标记的格式示例即可。翻译/校对状态必须允许后续编辑器阻止未准备好的生产条目进入正式批量合成。

验证真实发布编辑中的新增、删除、插入代理身份、角色归类和源文变更。提取逻辑应可被P4复用，现阶段不改游戏运行时。报告写入docs/voicevox/reports/T1.md。

## P2 — Sol：批量制作与可靠队列

在P1通过基础上，完成CSV/TSV及多文件批量导入，遵守技术提案的引号、多行、编码、重复ID及事务规则；支持搜索、角色/章节/状态筛选、多选批量改值、角色默认参数及撤销。预设保存在本工程，不修改引擎全局预设。

实现有持久化状态的串行生成队列、暂停派发、恢复、失败重试、取消、进度和按选择导出WAV/manifest。固定任务输入快照并防止过期结果覆盖当前编辑；缓存键覆盖有效AudioQuery、风格、引擎/core身份及所有合成选项。明确任务取消与引擎计算取消的差别。临时文件不能被识别为完成音频。

用模拟引擎覆盖连接中断、超时、无效WAV、重启恢复、取消后迟到结果及重复重试。用5,000条样例检查导入/筛选/调度响应，不做5,000次真实合成。Terra可承担Sol/Astra明确划定且不冲突的解析器或测试子任务。

## P3 — Sol：精细调音

实现按重音短语展示与编辑、重音位置、逐mora音高、可编辑音素时长、短语停顿、选句对比试听与撤销恢复。严格区分引擎原生风格和本工程的组合参数预设，不虚构通用情绪数值。

根据实际OpenAPI使用accent_phrases/mora_data/mora_pitch/mora_length；明确哪些接口会重算人工编辑字段。读音修改必须重新生成结构，不能仅修改AudioQuery.kana。处理无声mora、无辅音字段及边界值。改变文本、声音或重音结构之前保存可恢复快照，不能直接按数组下标移植旧调音。验证完整工程往返与针对性引擎请求，用户需要能直观找到当前修改的是哪个音节。

## P4 — Sol：游戏有效剧本与增量关联

研究并复用game/src/script-review-model.js、六篇剧情和script-edits.js的实际规则，导入当前已发布生效文本；不能直接执行用户导入的任意JS。保留章节、角色、源ID和内容hash；区分reviewId、运行时代理节点及真实台词，避免重复配音。默认排除演出/删除/无台词条目，旁白由用户选入。

定义并实现增量同步预览：新增/修改/删除/角色变化分别展示，保留人工speechText和调音历史，受影响音频标记过期。输出稳定ID WAV及可供游戏后续接入的manifest，不改变现有游戏运行时。针对已发布新增、插入、删除、分类改动与重复文本编写语义测试，不能只检查字段存在。
